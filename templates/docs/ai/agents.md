# Agents and skills

## Agents (`.claude/agents/`)

| Agent | Role | Can write | Sees | Returns |
|---|---|---|---|---|
| `researcher` | Gathers context, asks questions, estimates size | nothing (read-only) | task, code, specs, docs | research brief |
| `spec-writer` | Writes the OpenSpec change and the traceability report | `openspec/changes/<id>/` | research brief, your answers | summary + "Not from the task" list |
| `test-writer` | Writes failing tests for one sub-task and commits them | test files only | spec slice, public interfaces | RED commit, behavior → test map |
| `developer` | Makes the locked tests pass in its own worktree | source (no tests) | failing tests and output, `Files:` | commit, gate result |
| `reviewer` | Approves or requests changes | nothing (runs checks) | diff, spec, coding standards, team rules | verdict + findings |
| `feedback-curator` | Records durable feedback in the team rules, proposes repo rules | rules store; repo edits only via the orchestrator | your feedback quote | rule entry, proposed diff |

The orchestrator isn't an agent file: it is the `task` skill running in your main session, because only the
main session can ask you questions and wait for approval.

Every agent also gets the team rules for its role. The orchestrator reads that role's rules and pastes them into
the launch prompt (see `AGENTS.md` › External references).

All agents use `model: inherit`, so they run on the session's model. See [maintaining.md](./maintaining.md) to pin
one.

## Skills (`.claude/skills/`)

| Skill | Invoked by | Purpose |
|---|---|---|
| `task` | you (`/task`) | The orchestrator procedure: full and lite paths, resume, state file |
| `feedback` | you (`/feedback`) or the orchestrator | Hands general feedback to the curator |
| `task-intake` | orchestrator | Tracker task → normalized brief with verbatim requirements |
| `spec-traceability` | spec-writer | TASK / REPO / ASSUMED tagging and the short report |
| `subtask-split` | orchestrator | Independent sub-tasks → parallel waves |
| `quality-gate` | developer, reviewer, orchestrator | {{GATE_NAMES}} |
| `openspec-*` | spec-writer, orchestrator, you (`/opsx:*`) | OpenSpec workflows (generated by `openspec init`) |

## Enforcement

| Rule | How |
|---|---|
| Developer doesn't touch tests | Hook blocks test-file edits by `developer` (Claude Code) and edits to any locked test (both tools); reviewer checks `git diff <RED>..HEAD` on locked tests |
| Test writer doesn't touch source | Hook blocks non-test edits by `test-writer` (Claude Code); orchestrator checks `git show --stat <RED>` (both tools) |
| Researcher and reviewer don't edit | `readonly: true` (Cursor) / `disallowedTools` (Claude Code) on the researcher; `disallowedTools` plus instructions on the reviewer (it must run commands, so it isn't `readonly` in Cursor) |
| Parallel developers don't collide | `isolation: worktree` (Claude Code), explicit isolated-worktree request in the launch prompt (Cursor) |
